# 클릭 효과 전체 화면 오버레이 성능 문제

## 증상

마우스를 클릭할 때마다 Windows 트레이 영역의 방해 금지 상태가 켜졌다가, 클릭 효과가 끝나면 다시 꺼지는 현상이 있었다.

동시에 클릭할 때마다 컴퓨터 성능이 느려지는 것처럼 느껴졌다. 특히 연속 클릭 시 클릭 효과가 표시되는 동안 시스템 반응이 무거워질 수 있었다.

## 원인

트레이 아이콘 자체는 클릭할 때마다 변경되지 않았다. `Shell_NotifyIconW`는 앱 시작 시 `NIM_ADD`, 종료 시 `NIM_DELETE`만 호출하고 있었으므로, 사용자가 본 트레이 변화는 앱 아이콘 변경이 아니라 Windows의 방해 금지 상태 변화로 보는 것이 맞다.

실제 원인은 클릭 효과 창이 매 클릭마다 전체 가상 화면 크기의 최상위 팝업 윈도우로 표시되는 구조였다.

- 효과 창 스타일: `WS_POPUP`, `WS_EX_LAYERED`, `WS_EX_TRANSPARENT`, `WS_EX_TOPMOST`, `WS_EX_TOOLWINDOW`, `WS_EX_NOACTIVATE`
- 클릭 시 전체 가상 화면 크기로 `SetWindowPos`
- 16ms 타이머마다 전체 화면 크기의 RGBA 버퍼 생성
- 매 프레임 `CreateDIBSection`과 `UpdateLayeredWindow` 호출

이 때문에 Windows가 짧은 시간 동안 앱을 전체 화면 최상위 창처럼 판단해 자동 방해 금지 상태를 켰을 가능성이 높다.

또한 해상도가 클수록 `width * height * 4` 크기의 버퍼를 계속 새로 만들기 때문에, 클릭 효과 하나를 표시하는 데 비해 렌더링 범위가 과도하게 컸다.

## 수정

클릭 효과 창과 렌더 버퍼의 크기를 전체 화면이 아니라 현재 표시 중인 효과들을 감싸는 최소 사각형으로 줄였다.

- `Press`, `Ripple`, `Fade` 목록을 기준으로 활성 효과 영역 계산
- 계산된 영역을 가상 화면 범위 안으로 클램프
- 해당 영역 크기만큼의 작은 RGBA 버퍼 생성
- 그리기 좌표를 영역의 왼쪽 위 기준으로 변환
- `UpdateLayeredWindow`도 계산된 영역 위치와 크기로만 호출

효과가 없을 때는 기존처럼 타이머를 멈추고 `ShowWindow(hwnd, SW_HIDE)`로 숨긴다.

## 결과

수정 후 클릭 시 Windows 방해 금지 상태가 켜졌다 꺼지는 현상이 사라졌다.

전체 화면 버퍼를 매 프레임 만들지 않게 되어, 클릭 효과 표시 중의 렌더링 비용도 줄었다.

## 확인

- `src/effect.rs` 린트 오류 없음
- 실제 클릭 테스트에서 방해 금지 상태 변화가 재현되지 않음
